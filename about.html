Data Provenance & Security Information

To maintain absolute reliability and transparent authenticity, all script inputs, text elements, and recitation assets are derived directly from verified public repositories [1.2].

1. Primary Data Citation Links

We deeply respect and officially credit the foundational data streams that made this serverless compilation possible [1.2]:

  • Arabic Text & Tajweed Layer: Extracted directly from the official, trusted Quran.com API (v4) data tracks [1.2].
  • Word-by-Word Translation Mapping: Sourced via the Quran.com Network data clusters, originally compiled by the meticulous engineering team at QuranWbW.com [1.2].
  • Linguistic Text Interpretations: Structural Tafsir Ibn Kathir records and Maududi Surah metadata extracted directly from verified open API layers [1.2].
  • Audio Recitation Datasets: Raw audio assets are credited to the public archives at EveryAyah.com, covering 6 world-renowned Qaris (including Al-Sudais, Al-Shatri, Fares Abbad, Al-Muaiqly, Al-Ghamdi, and Al-Shuraim) [1.2].

2. Technical Build Pipeline Details

Instead of calling live server database clusters at runtime, our local backend utilizes a custom 10-script Python automation compiler [1.2]. The master pipeline processes the raw public datasets, filters out corrupted audio anomalies, and outputs optimized, minified static code maps straight into parallel local frontend tracks (../) [1.2]:

  • The textual scripts and 33 international translations are compiled into granular static JSON chunks partitioned cleanly by Hizb (Hizb 1-60) [1.2].
  • Audio files are compressed and translated into isolated Base64 text streams split across 240 Rub files per Qari to fully eliminate server-side CORS blocks [1.2].
  • The compiler automatically processes metadata boundaries to print the structural search indexes and pre-renders 604 physical Mushaf pages into /p and 114 native chapters into /s [1.2].

3. The Cryptographic Content Guard

Because decentralized file systems (IPFS) are inherently public, malicious actors could technically clone the repository files and attempt to tamper with translation targets or alter creator attribution paths [1.2].

To protect the absolute purity of the text, the compiled production frontend enforces a client-side integrity script [1.2]. It utilizes an optimized RC4 string array obfuscation engine split across a 4-chunk text layout tied directly to our verified canonical domain identities [1.2]. This layer successfully locks down text-validation hooks without triggering aggressive anti-virus packages or browser heuristic warnings, ensuring users always access an untampered, genuine environment [1.2].
